# Desktop app (`crates/desktop`)

The desktop app is a Tauri 2 host around the React UI in `ui/`. It runs the UI
in the system web view (WebView2 on Windows, WKWebView on macOS, WebKitGTK 4.1
on Linux) and implements the Rust side of the IPC contract in
[desktop-api.md](desktop-api.md). Every command and event of the contract is
implemented. This document covers the application state, the commands and
events, the transfer queue, configuration, security policy, icons, and
packaging.

| | |
|---|---|
| Cargo package | `bucketbridge-desktop` |
| Binary | `bucketbridge` (`bucketbridge.exe` on Windows) |
| Product name | BucketBridge |
| Identifier | `io.github.anupshaw50.bucketbridge` |
| Version | taken from `Cargo.toml` (`tauri.conf.json` has no `version` field) |
| Tauri | `tauri` 2.12, `tauri-build` 2.7, CLI `@tauri-apps/cli` 2.12 |
| Plugins | `tauri-plugin-dialog` 2.8, `tauri-plugin-opener` 2.7, `tauri-plugin-clipboard-manager` 2.5 (each with an npm package), `tauri-plugin-single-instance` 2.5 (Rust only) |

Keep each plugin crate on the same major.minor as its npm package in
`ui/package.json` (`@tauri-apps/plugin-dialog` 2.8, `@tauri-apps/plugin-opener`
2.7, `@tauri-apps/plugin-clipboard-manager` 2.5, and `tauri` 2.12 with
`@tauri-apps/api` 2.12). The CLI's own mismatch check only reads the root
`package.json`, which lists none of them, so this is not checked automatically.

The commands live in a library (`bucketbridge_desktop`) so that the tests can
drive them; the binary only calls `bucketbridge_desktop::run()`.

## Running and building

Run everything from the repository root after `pnpm install`. `pnpm tauri` is
the root `package.json` script that runs the Tauri CLI.

| Task | Command |
|---|---|
| Dev mode (Vite plus the app, Rust rebuilt on change) | `pnpm tauri dev` |
| Debug build without bundling | `pnpm tauri build --debug --no-bundle` |
| Debug bundle | `pnpm tauri build --debug --bundles app` (or `dmg`, `msi`, `appimage`, `deb`) |
| Release bundles for the current OS | `pnpm tauri build` |
| Universal macOS build | `pnpm tauri build --target universal-apple-darwin` (needs the `aarch64-apple-darwin` and `x86_64-apple-darwin` rustup targets) |
| Lint | `cargo clippy -p bucketbridge-desktop --all-targets -- -D warnings` |
| Configuration and environment report | `pnpm tauri info` |

### Hook commands and their working directory

```json
"devUrl": "http://localhost:5173",
"frontendDist": "../../ui/dist",
"beforeDevCommand":   { "script": "pnpm --dir ui dev",   "cwd": "../.." },
"beforeBuildCommand": { "script": "pnpm --dir ui build", "cwd": "../.." }
```

How the Tauri 2.12 CLI resolves these paths. This was checked against the CLI
source and by running the hooks.

1. The CLI looks for `tauri.conf.json` in the directory it was started from and
   up to three levels below it, which finds `crates/desktop`. It then changes its
   own working directory to `crates/desktop` before running any hook.
2. A relative `cwd` in the object form is therefore resolved from
   `crates/desktop`, so `../..` is always the repository root, whether the CLI is
   started from the root (`pnpm tauri ...`) or from `crates/desktop` (a
   cargo-installed `cargo tauri ...`).
3. The plain string form has no `cwd` and runs in the "frontend directory": the
   start directory if it contains a `package.json`, otherwise the first
   `package.json` found up to three levels below it, otherwise the parent of
   `crates/desktop` (that is, `crates/`). From the repository root this is the
   root, but from `crates/desktop` it is `crates/`, where `pnpm --dir ui` fails.
   This is why both hooks set `cwd`.
4. `frontendDist` is resolved from `crates/desktop` as well.

`tauri dev` starts `beforeDevCommand` in the background, waits until a TCP
connection to `localhost:5173` succeeds, then builds and starts the app. Vite
must listen on port 5173 with `strictPort: true`. Otherwise, when 5173 is busy,
Vite moves to another port and the app loads whatever is listening on 5173.

### Dev mode compared with a built app

- `tauri dev`: the web view loads `http://localhost:5173` from Vite. Tauri
  attaches the CSP only to files it serves itself, so **no CSP applies in dev
  mode**. Capability checks do apply.
- `tauri build` (also with `--debug`) enables the `tauri/custom-protocol`
  feature. It embeds `ui/dist` into the binary and serves it from
  `tauri://localhost` (macOS, Linux) or `http://tauri.localhost` (Windows) with
  the CSP header.
- A plain `cargo build -p bucketbridge-desktop` builds a dev-mode binary that
  loads `http://localhost:5173`. Release artifacts, including the portable
  Windows zip and the Linux tarball, must use the binary that `tauri build`
  produces. Because dev-mode builds embed nothing, `cargo check`, `clippy`, and
  `test` work without `ui/dist`.

Test CSP-sensitive UI behaviour against a built app
(`pnpm tauri build --debug --no-bundle`, binary `target/debug/bucketbridge`),
not against `tauri dev`.

## Application state and startup

`run()` registers the plugins in this order:

1. `tauri-plugin-single-instance`. A second launch hands over to the running
   app, which unminimizes, shows and focuses its main window. The second
   process exits there, before it opens anything.
2. The `bucketbridge` state plugin. It builds the `Core` and manages the
   `AppState`. Tauri initializes plugins in registration order while the app
   is built, before any window exists, so no command can arrive before the
   state is managed.
3. clipboard-manager, dialog and opener.

`Core::start()` runs at startup and blocks:

| Step | What |
|---|---|
| Folders | `Dirs::discover()` uses `$BB_CONFIG_DIR` (everything under one folder) or the platform folders, and creates them with mode 0700 |
| Instance lock | An exclusive OS lock on `data_dir/instance.lock`, held for the life of the process (see "Single instance") |
| Crash reporter | `crash::install(crash_dir, version)` |
| Session | `Session::open` keeps accounts and secrets on the OS keychain. Without a usable keychain it still opens, and secret operations fail with `io`. |
| Event log | An `EventLog` per `settings.logging` (level, file logging in `log_dir`), plus the global `tracing` subscriber that feeds it (see "Event log") |
| Sync | `SyncStore::open_in(dirs)` (`data_dir/sync`) and one `SyncExecutor` |
| Queue | `TransferQueue::open` over `data_dir/transfers.json` at `settings.transfer`, with the `S3Runner` task runners (see "Transfer queue"). Tasks saved by the last run come back `stopped`. |
| Bandwidth | The queue's `BandwidthLimiter` (`settings.transfer.bandwidth_limit_kibps`) is the app's one cap: it throttles queued transfers, every sync run and `open_object` |

When a step fails the app still opens. Examples are an unreadable
`config.toml`, a damaged `transfers.json`, or a data folder locked by another
process. `AppState` then holds the error, every command rejects with it and the
UI shows it. The error is also printed on standard error.

## Commands

Every command:

- is `async`, so it never runs on the UI thread;
- is declared with `#[tauri::command(rename_all = "snake_case")]`;
- rejects with `CommandError`, which serializes as the contract's `BbError`
  (`{ "code", "message" }`, from `bucketbridge_core::Error::to_payload`).

Blocking core work runs on the blocking thread pool: the configuration file,
the plan store, log export, crash reports and local folders. Passwords and MFA
codes arrive as `Secret` arguments, which are zeroized when dropped and
redacted in debug output.

| Command | Implementation |
|---|---|
| `security_status`, `unlock`, `lock`, `set_master_password` | `Session`. Status changes are broadcast and forwarded as `security://changed`. |
| `list_accounts`, `add_account`, `update_account`, `remove_account`, `set_default_account`, `mfa_login` | `Session` |
| `list_buckets`, `create_bucket`, `delete_bucket`, `create_folder` | `Session::s3_for(account_id)`, then `S3`. `list_buckets` also merges the external buckets pinned to the account (`S3::list_buckets_with_pinned`) |
| `get_bucket_config` and the `get_`, `put_`, `delete_` commands of the policy, public access block, versioning, logging, website and acceleration of a bucket; `validate_bucket_policy`, `format_bucket_policy` | `Session::s3_for(account_id)`, then the `bucketcfg` methods of `S3` (commands/bucketcfg.rs). The two policy text commands need no account |
| `list_external_buckets`, `add_external_bucket`, `remove_external_bucket` | `bucketcfg::pin_bucket` and `unpin_bucket` on `config.toml` through `spawn_blocking`; adding checks the bucket with `S3::verify_bucket_exists`. Listing and removing work while the secrets are locked |
| `list_objects` | `S3::list_objects` with `max_keys` set to `settings.advanced.list_page_size` |
| `presign` | `S3::presign_get` or `presign_put`. `expires_secs` must be 1 to 604,800, otherwise `usage`. |
| `open_object`, `open_object_with`, `open_bucket_in_browser` | See "Opening objects" |
| `enqueue_upload`, `enqueue_download`, `enqueue_copy`, `enqueue_move`, `enqueue_delete`, `rename` | `Session::s3_for(account_id)`, then the core's `engine::enqueue_*` helper on the queue. See "Transfer queue". |
| `list_tasks` | `TransferQueue::list` |
| `start_all`, `stop_all`, `cancel_all`, `clear_finished`, `pause_task`, `resume_task`, `cancel_task`, `retry_task` | The queue method of the same name. The queue's state machine (docs/transfers.md) answers `not_found` for an unknown id and `conflict` for a transition it does not allow. |
| `sync_analyze` | `S3::list_all` of the folder, then `sync::analyze` and `SyncStore::insert` on a blocking thread |
| `sync_execute` | Spawns `SyncExecutor::start` with a `TransferEngine` for the plan's account and `ExecuteOptions::new(settings, limiter)`, then returns at once |
| `sync_cancel` | `SyncExecutor::cancel`. A plan that is not running is left alone; an unknown plan is `not_found`. |
| `sync_get` | `SyncStore::get` |
| `list_versions`, `restore_version`, `purge_versions`, `enqueue_download_version`, `preview_object` | `Session::s3_for(account_id)`, then `S3::list_version_groups` (`max_groups` is `settings.advanced.list_page_size`), `restore_version`, `purge_versions`, `versions::enqueue_download_version` on the queue (the path must be absolute) and `S3::preview_object`. See "Versions and preview (T08)" in desktop-api.md. |
| `get_object_details`, `update_object_tags`, `set_object_storage_class`, `set_object_encryption`, `update_object_headers`, `set_object_acl` | `Session::s3_for(account_id)`, then `S3::object_details` and the batch methods of `bucketbridge_core::objectmeta` (up to 10,000 distinct keys, 8 at a time, one `ObjectChange` per key). SSE-C keys are `Secret` arguments: zeroized when dropped, redacted in debug output, never logged (the event log gets one line with counts per batch). `storage_class` and `acl` arrive as text so that an unknown value is a `usage` error. |
| `get_settings`, `save_settings`, `set_proxy_password` | `Session`. `save_settings` validates (every problem in one `usage` error), then applies the log settings to the running app and hands `settings.transfer` to the queue (`TransferQueue::update_settings`: concurrency, retries, part sizes and the bandwidth cap) and `settings.data_integrity` to the runners (`S3Runner::set_data_integrity`). |
| `get_log`, `export_log`, `clear_log` | `EventLog::query`, `export` and `clear` |
| `app_info` | Name, version (from `Cargo.toml`), license, repository URL, and the config, data and log folders |
| `last_crash_report`, `dismiss_crash_report` | `crash::last_report` and `crash::dismiss`. The core validates the path. |
| `run_diagnostics` | `diagnostics::probe_account` (a stored account: `locked`, `mfa_required` and `not_found` reject like any account command) or `probe_input` (an unsaved account of the wizard, nothing stored); a failing step is a result in the report. One line in the event log says whether every check passed or which steps failed. |
| `list_multipart_uploads`, `abort_multipart_uploads` | `S3::list_multipart_uploads` for each bucket (four at a time; a bucket that fails goes to `failures`) and `S3::abort_multipart_upload` one upload after the other with a result each |
| `list_filters`, `save_filter`, `delete_filter` | `saved_filters::{list, save, delete}` on the configuration store, on a blocking thread |
| `export_listing` | `export::export_listing` with the account's `S3` handle; `path` must be absolute (`usage`). The file is replaced only by a complete export. |

Paths from the UI must be absolute, otherwise the command rejects with
`usage`. This covers `local_root`, the `export_log` path, every entry of
`local_paths` in `enqueue_upload` and `dest_dir` in `enqueue_download`. The UI
takes them from the native dialogs and from files dropped on the window, and a
relative path would depend on the app's working directory.

Failures that point at something broken are also recorded in the event log,
together with the operation, for example `listing objects failed:
s3://bucket/x: Access Denied`:

- `remote`, `io` and `internal` are recorded as errors.
- Authentication failures are recorded as warnings.
- Ordinary answers are not recorded: usage errors, missing items, conflicts,
  locked secrets, missing MFA sessions and cancellations.

Tauri rejects malformed IPC arguments before the command runs: a missing key,
a wrong JSON type or an unknown enum value. The rejection is a plain string
instead of a `BbError`, which the UI maps to `internal`.

## Events

| Event | Source |
|---|---|
| `security://changed` | `Session::subscribe()`, forwarded by a task started at startup |
| `log://entry` | `EventLog::subscribe()`, forwarded the same way. The log only records entries at or above `settings.logging.level`, so only those are sent. |
| `sync://progress`, `sync://row` | The `SyncEvents` of each run (`SyncEmitter` in `events.rs`) |
| `transfer://update`, `transfer://removed` | `TransferQueue::subscribe()`, forwarded by a task started at startup: `QueueEvent::Updated` is `transfer://update` and `QueueEvent::Removed` is `transfer://removed` (`{ "ids": [...] }`). `QueueEvent::PersistFailed` is not sent to the UI: it is written to the event log as an error from source `bucketbridge::transfer`. |

A forwarder that falls behind skips to newer items. The queue forwarder is the
exception: the queue never drops an event and the forwarder never skips or
batches one, so the UI sees every state change in the order it happened. The
queue itself sends at most one progress update per running task every 250 ms. A run can end before it
reports `finished: true`, for example when its plan cannot be loaded. The host
then sends a final `sync://progress` with `finished: true` itself, so the UI
never waits for an end that does not come. The event log also records how
every run ended (source `bucketbridge::sync`).

## Transfer queue

`Core` owns one `TransferQueue` (`bucketbridge_core::transfer`,
[transfers.md](transfers.md)) and the `engine::S3Runner` task runners
([engines.md](engines.md)). The commands only enqueue and control; the queue
schedules, runs, retries and persists the tasks.

| Part | Wiring |
|---|---|
| Opening | `Core::build` opens the queue with `tauri::async_runtime::block_on`, at `settings.transfer`, persisted in `data_dir/transfers.json` (the queue saves one second after a change, atomically). `QueueOptions::stop_grace` is five seconds. |
| Runners | One `S3Runner` for every task kind. Its provider calls `Session::s3_for(account_id)` at the start of every run and cleanup, so a task always runs with the account's current credentials. |
| Bandwidth | `Core::limiter` is the queue's own limiter (`TransferQueue::limiter()`), not a second one. `save_settings` changes it through `TransferQueue::update_settings`, and waiting transfers adopt the new rate at once. |
| Settings | `save_settings` calls `TransferQueue::update_settings(settings.transfer)` (a higher concurrency starts queued tasks at once, a lower one never interrupts running tasks, retries and part sizes apply to the next failure or run) and `S3Runner::set_data_integrity(settings.data_integrity)` (checksums and download validation of the runs that start from then on). |
| Events | `QueueEvent::Updated` becomes `transfer://update`, `Removed` becomes `transfer://removed`, `PersistFailed` becomes an error in the event log (see "Events"). |

Enqueueing:

- Every `enqueue_*` command and `rename` first resolves the account with
  `Session::s3_for`, so an unknown account (`not_found`), locked secrets
  (`locked`) and a missing MFA session (`mfa_required`) reject the command. An
  upload and a delete send nothing to S3 at that point, but are checked the
  same way, so that a locked account rejects the command instead of failing
  its tasks later.
- The selection is expanded by the core ([engines.md](engines.md), "Expansion"):
  the folder semantics of the contract, one `group_id` for all tasks of a call,
  and `conflict` with nothing queued when two selected sources would land on
  the same destination or a rename's destination exists. Bucket names are
  checked (`usage`). An empty selection returns `[]`.
- An entry that cannot be added (an unreadable local file, an unsafe key, a
  folder that cannot be listed, `/` as a delete key) becomes a `failed` task
  with the reason in `error`, next to the tasks of the entries that could be
  added. `retry_task` fails it again with the same reason and `cancel_task`
  touches nothing.

Running:

- A task that starts while the secrets are locked, or the account needs an MFA
  session, fails (`locked` and `mfa_required` are not retried). Unlock, or log
  in with MFA, and call `retry_task`. A run that is already executing keeps
  its client and finishes when the app is locked; the automatic retries of a
  run that fails meanwhile ask the session again and fail the same way.
- A failed upload keeps its multipart upload, so that automatic retries and
  `retry_task` continue with the finished parts. `cancel_task` aborts it. The
  abort needs the account's credentials: cancelling while the secrets are
  locked, or the MFA session has expired, still ends the task as `cancelled`,
  with the failed cleanup in its `error`, and the multipart upload stays on S3
  until it is aborted there.

Persistence: after a restart, `queued` and `running` tasks come back `stopped`
with their resume state, in their old order, and `start_all` or `resume_task`
continues them (a multipart upload with its finished parts, a download from its
partial file). Completed, cancelled and failed tasks are kept until they are
cleared, retried or cancelled. A queue file that cannot be read (damaged, or
written by a newer version) stops the startup like an unreadable `config.toml`:
the error names the file, which is left untouched, and starting with an empty
queue means moving it away. A background save that fails is written to the
event log as an error and tried again with the next change; the queue keeps
working in memory.

## Single instance

The plan store and the transfer queue file assume a single process. Two
mechanisms protect them:

- **`tauri-plugin-single-instance`** turns a second launch into a focus of the
  first window (the `main` window, or another window of the app when `main`
  was closed). It uses a Unix socket on macOS, a D-Bus name on Linux and a
  named mutex on Windows. The second process exits before it opens the
  session or any store.
- **The data-folder lock** covers what the plugin cannot see. It is an OS file
  lock on `data_dir/instance.lock`, released when the process ends, also after
  a crash. One example: on macOS the plugin's socket lives in `/tmp`. When it
  belongs to another user, the plugin lets the launch continue.
  - A process that cannot get the lock starts in the failed state with
    `conflict`: "BucketBridge is already running with the data folder ...".
  - On a file system without locks, the app reports this on standard error
    and continues.

## Opening objects (`open_object`)

1. A folder key (ending in `/`) is rejected with `usage`.
2. The download engine fetches the object into a new folder
   `data_dir/open/<uuid>/`, with mode 0700 on Unix so other users cannot read
   the copy. `TransferOptions` come from the settings (for example download
   validation), and the shared bandwidth limiter throttles the download.
3. The file name is the key's last segment, made valid on every OS:
   - characters that Windows forbids and control characters become `_`;
   - trailing dots and spaces are removed;
   - device names such as `CON` get a `_` prefix;
   - long names are shortened, keeping the extension so the OS picks the
     right application.
4. `tauri_plugin_opener::open_path` opens the file with the default
   application. This is a Rust call, not a JS call, so the capability does not
   need `opener:allow-open-path`.

`open_object_with` runs steps 1 to 3, then opens the copy with the chosen
application through the `OpenWith` seam (`tauri_plugin_opener::open_path` with
the application as its program: an `.app` bundle on macOS, an executable on
Windows and Linux). Once the application started it moves to the front of
`settings.general.open_with_recent` (at most 8, no duplicates). A blank
application is `usage`.

`open_bucket_in_browser` computes the bucket address and hands it to the
`UrlOpener` seam (`tauri_plugin_opener::open_url`, a Rust call, so it needs no
`opener:allow-open-url` permission). AWS: `https://<bucket>.s3.<region>.amazonaws.com/`,
or `https://s3.<region>.amazonaws.com/<bucket>` when the name has a dot;
custom endpoint: `<endpoint>/<bucket>` for path style, else the bucket in the
host name. Tests replace both seams with recorders (`CoreParts::open_with`,
`CoreParts::url_opener`).

A failed download removes its folder. Copies are kept while the app runs,
because the application showing one may still need it, and are deleted at a
later start once they are a day old.

## Event log

`logging.rs` installs the global `tracing` subscriber with the event log's
layer. It records:

- information and above from BucketBridge's own targets (`bucketbridge*`:
  `bucketbridge::app`, `bucketbridge::desktop`, `bucketbridge::sync`);
- warnings and errors from dependencies.

No command logs its arguments, and passwords are `Secret` values, so no secret
reaches the log.

## Shutdown

On `RunEvent::Exit` the app:

1. stops the transfer queue. It refuses further commands (`conflict`), turns
   queued tasks into `stopped` and asks running transfers to pause. They get
   five seconds (the queue's `stop_grace`; what is still running after that is
   dropped), then the queue file is saved with every unfinished task `stopped`
   and its resume state, so the next start continues it;
2. at the same time, cancels every running sync run. The engines abort
   multipart uploads and delete partial files, and the rows stay pending, so
   the next `sync_execute` resumes. The runs get up to 5 seconds to end;
3. waits for the queue to finish saving;
4. flushes the log file.

Both waits overlap, so the app needs about five seconds at most, plus the final
save. Locking the secrets (`lock`) does not stop runs that are already
executing, in the queue or in sync. They keep their clients and finish.

## Tests

`cargo test -p bucketbridge-desktop` runs two sets:

- unit tests for the file names and folders of `open_object`;
- the IPC tests in `tests/ipc/`.

Each IPC test builds a mock-runtime app (`tauri::test`, with the `test`
feature on a dev-dependency). The app has the real handler and a `Core` over a
temporary folder, `Session::open_with` and an in-memory secret store. The test
invokes commands through Tauri's IPC path with the JSON the UI sends:
`snake_case` keys and `null` for optional values. Results and rejections are
asserted as JSON, checking contract shapes and `BbError` codes. S3 is the
in-process test server of `bucketbridge-tests`, and `open_object` uses a
recording opener instead of launching applications.

| Area | Covered |
|---|---|
| Accounts | Lifecycle, default account, duplicate label (`conflict`), empty label (`usage`), unknown ids (`not_found`) |
| Security | Setting, changing and removing the master password; lock; wrong password (`auth`); `locked` commands; `security://changed` |
| MFA | An account with an MFA serial and no session (`mfa_required`) |
| Browsing | Buckets; paginated listings with the page size from the settings; folders first; flat listings; folder markers; `not_found`; non-empty bucket (`conflict`); invalid names (`usage`) |
| Presign | GET and PUT URLs used over HTTP; expiry limits |
| Bucket configuration | Every section round-tripped through IPC (read, write, read again) on `BucketConfigMock`; a refused or unimplemented section not hiding the others; invalid policies and websites rejected with nothing sent; `usage` for acceleration on a custom endpoint; `not_found`, `locked` and `mfa_required` of every account-bound command; external buckets pinned, merged, surviving a restart, removed with their account, usable while locked |
| Open | Download into the private folder, file name, folder mode, folder keys and missing objects |
| Sync | Analysis shape, dry run, execution with `sync://progress` and `sync://row`, resume, re-analysis, `usage` / `not_found` / `conflict`, shutdown cancelling a throttled run |
| Object metadata | Details shape; an SSE-C object needing its key, a wrong key failing with `auth` and a message about SSE-C, a malformed key being a `usage` error that does not echo it; tag batches with per-key results and partial failures; storage class changes and archived objects (`conflict`); encryption changes and a wrong source key changing nothing; header patches, canned ACLs and ACLs disabled; unknown account |

## Window and menu

One window, declared in `tauri.conf.json` and created at startup. The
`open_new_window` command (docs/desktop-api.md, "Bookmarks and windows (T14)")
opens more windows of the same process, labelled `main-1`, `main-2`, and so on,
built with `WebviewWindowBuilder` over the bundled `index.html`. They share the
one `Core` in the managed `AppState`, and events go out with `app.emit`, which
reaches every window. A new window copies the size of the calling window and is
cascaded by 32 points. The `main` window is described here:

| Setting | Value | Why |
|---|---|---|
| `label` | `main` | Referenced by the capability |
| `title` | BucketBridge | |
| `width` x `height` | 1280 x 800 | Room for the bucket tree, the object list, and the transfer panel |
| `minWidth` x `minHeight` | 960 x 600 | Keeps the toolbar and two panes usable; fits 1366 x 768 laptop screens |
| `center` | `true` | |
| `preventOverflow` | `true` | Shrinks the window to the screen's work area on small displays |
| `dragDropEnabled` | `true` | Files dropped from the OS file manager arrive through `getCurrentWebview().onDragDropEvent()`. On Windows this also turns off HTML5 drag and drop inside the page. |
| `generalAutofillEnabled` | `false` | Stops WebView2 from storing and suggesting values typed into form fields such as key IDs, endpoints, and bucket names. No effect on other platforms. |

On macOS, WKWebView receives Cmd+C, Cmd+V, Cmd+X, Cmd+A, Cmd+Z, and
Shift+Cmd+Z only when the application menu has the matching Edit items.
`src/menu.rs` therefore installs a small menu built from predefined items:

- App menu: About, Services, Hide, Hide Others, Show All, Quit.
- Edit: Undo, Redo, Cut, Copy, Paste, Select All.
- Window: Minimize, Zoom, Close Window.

Windows and Linux get no menu bar, because their web views handle these
shortcuts without one. Closing the window quits the app on every platform.

## Content Security Policy

`app.security.csp` in `tauri.conf.json`:

| Directive | Value | Reason |
|---|---|---|
| `default-src` | `'self'` | Fallback for every fetch type not listed (media, workers, manifests): only files from the app bundle |
| `script-src` | `'self'` | Only bundled JavaScript. No inline handlers, no `eval` or `new Function`, no remote scripts. |
| `style-src` | `'self' 'unsafe-inline'` | Bundled CSS plus inline styles. Mantine inserts `<style>` elements at runtime (theme variables, responsive style props) and sets `style` attributes, and both need `'unsafe-inline'`. |
| `img-src` | `'self' data: blob:` | Bundled images, `data:` URIs (small assets Vite inlines, CSS icons), and `blob:` object URLs for previews built from bytes that a command returned |
| `font-src` | `'self'` | Bundled fonts only (Mantine uses system fonts by default), no font CDNs |
| `connect-src` | `'self' ipc: http://ipc.localhost` | Tauri IPC (`ipc://localhost` on macOS and Linux, `http://ipc.localhost` on Windows) and same-origin requests. The web view cannot reach S3 or any other host. All network I/O goes through Rust commands. |
| `object-src` | `'none'` | No plugin content |
| `frame-src` | `'none'` | No iframes |
| `base-uri` | `'none'` | A `<base>` element cannot redirect relative script URLs |
| `form-action` | `'none'` | Forms cannot submit or navigate. Handle submit in JS with `preventDefault()`. |

`app.security.dangerousDisableAssetCspModification` is `["style-src"]`. At build
time Tauri adds a nonce to every `<style>` element in the HTML files and puts
that nonce into `style-src`. Browsers ignore `'unsafe-inline'` once a directive
contains a nonce, so a single `<style>` in `index.html` would block all of
Mantine's runtime styles, and only in the built app. Turning the modification
off for `style-src` only keeps the policy exactly as written. `script-src`
modification stays on: Tauri adds the SHA-256 hashes of the bundled scripts,
which only narrows the policy.

What the UI must respect:

- Load nothing remote: scripts, styles, fonts, and images come from the bundle.
  Object previews and thumbnails come from commands as bytes and are shown
  through `blob:` URLs.
- Do not use `eval`, `new Function`, or string timers. Libraries that compile
  code at runtime work in `tauri dev` and fail in the built app.
- Runtime `<style>` elements and `style` attributes are fine.

Verified on macOS with a stand-in page in a debug bundle. Bundled CSS, a
runtime `<style>` element, a `style` attribute, `data:` and `blob:` images, and
event IPC all worked, with no CSP violation for `ipc:`. Remote images, remote
`fetch`, and `eval` were blocked. Under `tauri dev` the same page could call
`eval` and reported no violations, which confirms that the CSP does not apply
there.

`app.security.freezePrototype` is left off, because freezing `Object.prototype`
breaks third-party code that assigns properties such as `toString` on plain
objects. It can be enabled once the UI's end-to-end suite passes with it on.

## Capabilities

`capabilities/default.json` (identifier `default`) applies to the `main` window
and the windows opened by `open_new_window` (the pattern `main-*`)
on Linux, macOS, and Windows, for the bundled UI only (no remote origins).
Every file in `capabilities/` is active, so keep it to this one file unless a
second window is added.

| Permission | Used for |
|---|---|
| `core:event:allow-listen`, `core:event:allow-unlisten` | `transfer://*`, `sync://*`, `log://entry`, `security://changed` events, and OS file drops (`onDragDropEvent`) |
| `dialog:allow-open`, `dialog:allow-save` | File and folder pickers: upload sources, download destination, sync root, log export path |
| `dialog:allow-message` | `message()`, `ask()`, and `confirm()`. In plugin-dialog 2.8 all three use the `message` command. `dialog:allow-ask` and `dialog:allow-confirm` are deprecated aliases of this permission and are removed in v3. |
| `opener:allow-open-url`, scoped | Opens `https://github.com/anupshaw50/BucketBridge` and anything below `https://github.com/anupshaw50/BucketBridge/` in the default browser (About, help, license, issue links). Any other URL is rejected. |
| `opener:allow-reveal-item-in-dir` | "Show in folder" for downloaded files. The plugin has no scope for this command, but it only highlights a path in the file manager. |
| `clipboard-manager:allow-write-text` | Copy-to-clipboard fields: keys, S3 paths, presigned URLs |
| `clipboard-manager:allow-write-secret` | Copying generated passwords and secret keys with `writeSecret()`, which keeps them out of clipboard history and clipboard managers |

Deliberately not granted:

- **Clipboard reading**, because any script in the page could read whatever
  the user copied (passwords included). Pasting into text fields, including S3
  paths in the address field, works natively through the Edit menu or the
  keyboard shortcut without the plugin. Cut, copy, and paste of S3 objects
  (§4.11 toolbar) is an in-app clipboard of selected keys, not the system
  clipboard. `readText()` rejects.
- **`opener` open-path**: opening objects locally is the `open_object` command,
  which uses the plugin's Rust API, and capabilities do not restrict that.
- **`core:window`, `core:app`, `core:path`, `core:webview`, `core:menu`, and
  event `emit`**: the UI does not need them. App name, version, and directories
  come from the `app_info` command. Path helpers such as `basename` from
  `@tauri-apps/api/path` are rejected, so use plain string handling.
  `getCurrentWindow().onCloseRequested()` would also need
  `core:window:allow-destroy`.

With `build.removeUnusedCommands`, builds started by the Tauri CLI (`tauri dev`
and `tauri build`) leave every plugin command that is not granted out of the
binary. Examples are clipboard `read_text`, all of `fs` (which plugin-dialog
pulls in), opener `open_path`, and the core window, app, and path commands. A
call to one of them is rejected by the capability check, and the error names the
missing permission, for example `clipboard-manager.read_text not allowed`. To
grant one, add the permission to `capabilities/default.json`. The build
validates every identifier and fails on unknown ones.

## Icons

`icons/icon.svg` is the source: a white bucket whose rim doubles as the deck of
a tied-arch bridge, on a teal-to-blue rounded tile. The tile follows the 824 px
macOS icon grid inside a 1024 px canvas, which leaves a transparent margin.

Regenerate the set from the repository root:

```sh
pnpm tauri icon crates/desktop/icons/icon.svg
rm -r crates/desktop/icons/android crates/desktop/icons/ios
```

The command rasterizes the SVG at every size, and the second line removes the
mobile icons, since the app is desktop-only. Files:

## Bundles

`bundle.targets` is `["app", "dmg", "msi", "appimage", "deb"]`. The CLI keeps
the entries that apply to the build host, so a plain `pnpm tauri build` makes
app and dmg on macOS, msi on Windows, and appimage and deb on Linux. `--bundles`
overrides the list.

Metadata shared by every bundle: publisher "Anup Shaw (anupshaw50)",
homepage https://github.com/anupshaw50/BucketBridge, copyright "Copyright (C)
2026 Anup Shaw (anupshaw50)", license GPL-3.0-only, category `DeveloperTool`,
and the short and long descriptions in `tauri.conf.json`. `bundle.licenseFile`
is not set, because it would add a click-through license agreement to the DMG
and the MSI; the GPL needs no acceptance to run the program, and every archive
ships the `LICENSE` file.

Artifacts, under `target/release/bundle/` (`target/debug/bundle/` with
`--debug`, `target/<triple>/release/bundle/` with `--target`):

| OS | Artifact |
|---|---|
| macOS | `macos/BucketBridge.app`, `dmg/BucketBridge_<version>_<arch>.dmg` (`aarch64`, `x64`, or `universal`) |
| Windows | `msi/BucketBridge_<version>_x64_en-US.msi` |
| Linux | `appimage/BucketBridge_<version>_amd64.AppImage`, `deb/BucketBridge_<version>_amd64.deb` |

The raw binary for the portable Windows zip and the Linux tarball is
`target/release/bucketbridge.exe` or `target/release/bucketbridge`, as written
by `tauri build`.

### macOS

- `LSMinimumSystemVersion` and the deployment target are `11.0`. The arm64
  slice cannot go lower, and Vite 8's default build target (Safari 16.4) needs a
  WebKit that macOS 11 and later receive through system updates.
- Category `public.app-category.developer-tools`. Hardened runtime is on (the
  default), and no extra entitlements are needed.
- Signing and notarization read the standard environment variables:
  `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY`,
  then either `APPLE_ID`, `APPLE_PASSWORD`, and `APPLE_TEAM_ID`, or
  `APPLE_API_KEY`, `APPLE_API_ISSUER`, and `APPLE_API_KEY_PATH`. Without them
  the bundle keeps the linker's ad hoc signature. That runs locally, but
  Gatekeeper blocks it when it is downloaded.
- With `CI=true` (set by CI runners) the DMG step skips the Finder window
  styling. Without it, the step drives Finder through AppleScript, which macOS
  may first ask the user to allow.

### Windows

- MSI built with WiX 3, which the bundler downloads on first use. Language
  `en-US`.
- `bundle.windows.wix.upgradeCode` is pinned to
  `9007ebcf-3edf-51a1-bab5-e9c1a0a5e61b`, the value Tauri derives from the
  product name (`tauri inspect wix-upgrade-code`). It must never change, or
  upgrades install side by side.
- MSI versions must be numeric `major.minor.patch`. A pre-release version
  needs `bundle.windows.wix.version`.
- WebView2: default `downloadBootstrapper` mode. The installer fetches the
  runtime only when it is missing (Windows 10 and 11 normally have it). The
  portable zip relies on the installed runtime.
- The C runtime is linked statically (Tauri default), so no Visual C++
  redistributable is needed.
- Signing is not configured in the repository. Set
  `bundle.windows.certificateThumbprint` or `bundle.windows.signCommand` in CI
  through a config override (`tauri build --config <json>`).

### Linux

- deb: package name `bucket-bridge` (Tauri derives it from the product name),
  section `net`, priority `optional`, maintainer "Anup Shaw (anupshaw50)".
  `Depends: libwebkit2gtk-4.1-0, libgtk-3-0` is added by the CLI itself on
  Linux, so the config does not repeat it. `Recommends: xdg-utils`, because
  the opener plugin opens URLs with `xdg-open`. The desktop entry is
  `BucketBridge.desktop` with `Categories=Development;`.
- AppImage: bundles the GTK and WebKitGTK libraries. GStreamer is not bundled,
  since the app plays no media. The bundler downloads linuxdeploy at build time.
- The tarball's raw binary needs `libwebkit2gtk-4.1-0` and `libgtk-3-0` on the
  target system.
- Build hosts need the WebKitGTK 4.1 development package
  (`libwebkit2gtk-4.1-dev` on Debian and Ubuntu, which pulls in GTK 3), a C
  toolchain, and `file` for AppImage packaging.

## Privacy

There is no updater plugin and no telemetry, and the web view cannot open
network connections (`connect-src`). The app talks only to the S3 endpoints the
user configures, through Rust. Downloads of WiX, linuxdeploy, and the WebView2
bootstrapper happen on the build machine or in the Windows installer, never in
the running app.

## Command permissions

App commands are allowed for the main window without per-command permissions,
because there is no application ACL manifest. An app manifest
(`tauri_build::Attributes::app_manifest`) could require an `allow-<command>`
permission per command in `capabilities/default.json`. `removeUnusedCommands`
would then also compile out ungranted commands.
