# 界面汉化指南（简体中文）

BucketBridge 的界面文案是**英文源 + 中文语言包**：源码里保留英文句子，`tr()` 在运行时把它换成中文。
语言跟随系统（`navigator.language` 以 `zh` 开头时用中文），否则用英文；也可以在「设置 → 界面 → 语言」里手动切换。

## 机制

| 文件 | 作用 |
| --- | --- |
| `ui/src/i18n/locale.ts` | 当前语言（`zh-CN` / `en`），存 localStorage，切换时通知订阅者 |
| `ui/src/i18n/index.ts` | `tr(英文, 变量?)` 查中文；`t(键)` 取菜单文案；`hasTranslation()` 供测试用 |
| `ui/src/i18n/zh/<区域>.ts` | 每个目录一份中文表，键是英文原文，值是中文译文 |
| `ui/src/i18n/zh/menu.ts` | 菜单文案（类型 `Messages`，少一个键就编译不过） |
| `ui/src/i18n/coverage.test.ts` | 覆盖率测试：每个 `tr("…")` 都必须登记，且不能两处译得不一样 |

## 源码改写规则

只改字符串字面量，**不改任何逻辑、结构、属性名**。

### 先判断文案的来源

`tr()` 只能翻译**界面源码里写出的句子**。这些不要包：

- **Rust 侧返回的错误与消息**（`BbError.message`、`crates/core` 的诊断），它们在界面里原样显示，
  翻译属于后端范围，不在本次汉化内。
- **mock 后端 / fixture 数据**里的英文（演示桶名、演示通知、示例策略），它们是数据，不是界面文案。
- 文件名、桶名、账户标签等用户数据。

反过来：**测试里**只有当这句话确实由界面源码产生时才包 `tr()`；
断言 mock 返回的英文、Rust 返回的英文、fixture 里的英文时保持原样。

### 要包 `tr()`

1. JSX 属性：`label="New bucket…"` → `label={tr("New bucket…")}`
2. JSX 文本：`>New folder<` → `>{tr("New folder")}<`
3. 对象属性：`label: "Overwrite"` → `label: tr("Overwrite")`
4. 字符串拼接 / 模板字符串（有插值的）改用占位符：

   ```ts
   // 之前
   model.status.error(err, { notify: `Deleted ${n} files` });
   // 之后
   model.status.error(err, { notify: tr("Deleted {n} files", { n }) });
   ```

5. 抛给用户的错误：`throw new Error("Too many attempts")` → `throw new Error(tr("Too many attempts"))`
   （只翻能到达状态栏/通知的；`console.*`、tracing 日志、程序内部断言不要翻）

### 不要包 `tr()`

- **值不是给人看的**：`value=`、`id=`、`key=`、`code=`、`name=`（状态枚举）、`data-testid`、
  路由/查询参数、事件名、CSS 类名、颜色、正则、日期格式（`YYYY-MM-DD`）。
  例：`{ value: "overwrite", label: "Overwrite" }` 只包 `label`。
- **品牌与技术名词**：BucketBridge、Amazon S3、S3、AWS、CloudFront、IAM、MFA、CORS、ACL、
  URL、API、HTTP(S)、JSON、CSV、Parquet、XLSX、Glacier、SSO、STS、SHA-256、CRC32 等，
  直接保留原文（也不用包 `tr()`）。
- 数字与日期的格式（`toLocaleString("en-US")`、文件大小 KB/MB）保持不变。
- `mock/` 目录（浏览器演示数据）不翻。
- 菜单里已有的英文（见 `zh/menu.ts`）通常不用重复登记；只有需要不同译法时才在区域文件里覆盖。

### 占位符

- 句子内部用 `{名字}`，如 `tr("Copied {n} objects", { n })`。
- 占位符必须**写在英文原句里**，中文译文里也要有同样的 `{名字}`。
- `tr()` 的调用保持**单行**，用双引号；句中需要引号时转义 `\"`。

## 测试改写规则

测试跑在英文环境（`src/test/setup.ts` 每个用例前设为 `en`，英文是默认语言）。断言要**跟着界面语言走**，
所以统一用 `tr()` 包住英文原文，这样中英文两种语言下都能过；需要测中文的用例自己调用 `setLocale("zh-CN")`：

```ts
import { tr } from "../../i18n"; // 路径按测试文件所在位置调整

await user.click(screen.getByRole("button", { name: tr("Add account…") }));
expect(screen.getByText(tr("Upload failed"))).toBeInTheDocument();
```

- `getByRole(..., { name: "…" })`、`getByLabelText`、`getByPlaceholder`、`getByTitle` 里的可见文字都要包。
- `expect(...).toContain("…")` / `toHaveTextContent("…")` 同样包 `tr()`。
- 带插值的断言：要么传同样的变量，要么只断言前缀
  （`expect(...).toContain(tr("Deleted {n} files", { n: 3 }))` 或 `expect.stringContaining(tr("Copied"))`）。
- 与文案无关的（结构、`data-*`、枚举值）不要动。
- 菜单形状测试里的英文标签同样用 `tr()`。

### 中文排版

- 用中文标点（，。：；？！「」），省略号沿用 `…`，**不要用长破折号**（项目不允许）。
- 英文、数字与中文之间留一个半角空格：`已删除 3 个文件`。
- 语气统一：按钮用动词短语（「上传文件…」），提示用完整句子（「请先打开一个存储桶。」）。
- 结尾的 `…` 表示会打开对话框，保留。

## 自检

在 `ui/` 目录下（或仓库根 `pnpm --dir ui …`）：

```bash
pnpm --dir ui typecheck                # 类型（含 zh/menu.ts 缺键）
pnpm --dir ui lint                     # eslint
pnpm --dir ui test --maxWorkers=4      # 全量测试
pnpm --dir ui test --maxWorkers=2 src/i18n   # 覆盖率：每个 tr() 都有中文
```
